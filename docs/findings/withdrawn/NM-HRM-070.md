## Why it was withdrawn

**Pages 249 and 265 time the disk data stream, and nothing else.** p. 265:

> 08 FAST   Disk data clock rate control 1=fast(2us) 0=slow(4us).

p. 249, Table 8-8:

> Value of 1 selects two microseconds per bit cell (usually MFM). Data must be valid raw MFM. 0 selects four microseconds per bit (usually GCR).

That clock is the one on Paula's write-data pin, p. 380: `38 DKWD* Disk write
data O`. `nanomig.v` has no such port. Its disk side is the SD-card sector
interface (`sdc_*`), so the stream the two pages time cannot be observed where
the packages observe.

**The packages timed something else: the disk DMA's reads of Chip memory.**
They divided the interval between two reads by sixteen cells a word, on the
premise that one read occurs per word sent. No page says so. p. 279 makes a
DMA word sixteen raw bits on the disk:

> This register is the disk DMA data buffer. It contains two bytes of data that are either sent (written) to or received (read) from the disk.

It does not say when the next word is taken from memory, or that this register
is the only storage between memory and the pin. p. 194 lets a device leave its
slots unused, "If a device does not request one of its allocated time slots,
the slot is open for other uses", and pp. 380-381 name Paula's `DMAL`, "DMA
request line", and no more. For audio, p. 164 prints when a request goes out;
for disk, no page does. The reads-to-cells relation was the packages' model,
and the reds measured the model.

**The bands were the packages' as well.** 1.5 ≤ T < 2.5 µs and 3.5 ≤ T < 4.5 µs
read "2us" and "4us" at one significant figure. `G3`'s three-line band on
|D_S − 2 D_F| assumes an exact factor of two, which `integration/ch8-disk-serial`
declines "because no page states one".

**The measurements stand as measurements.** Disk write DMA reads 512 words in
310520 cycles, three a line in the disk slots, the same to the cycle with
ADKCON bit 8 set and clear, on both cores. In the source, bit 8 is stored,
read back and routed nowhere ([`paula.v#L137`](https://github.com/harbaum/NanoMig/blob/4315acba5e9f1e15103037627aa78b3460cae8af/src/minimig-aga/paula.v#L137),
[`#L203`](https://github.com/harbaum/NanoMig/blob/4315acba5e9f1e15103037627aa78b3460cae8af/src/minimig-aga/paula.v#L203)),
which [`hrm/ch8-adkcon-disk-control-bits`](../../../hrm/ch8-adkcon-disk-control-bits)
records. None of this contradicts a printed sentence that a test at
`nanomig.v` can show: the function p. 265 gives the bit acts on a stream this
boundary does not have.

**Condition for filing again.** A printed page that ties the rate of the disk DMA's reads of Chip memory to the bit cell, or a boundary at which the write-data stream is observable, would reopen the claim; neither pp. 249, 265, 279 nor pp. 380-381 does.
